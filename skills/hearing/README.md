# hearing

## 概要

顧客ヒアリングの会議に向けて、営業メモや既知情報から「この場で聞くこと」と進行の台本を作り、会議後には発言をもとにボトルネック仮説と次回の確認事項を残す。会議前は `mode:prep`、会議後は `mode:analysis` を使う。

## 利用メリット

- 初めてのヒアリングでも、重要な点を押さえた質問紙を準備できる。
- 会議中に次の問いが手元にあるので、「今何を聞くか」にその場で迷いにくい。
- 会議後に仮説と次回質問が残るので、録音やメモを読み返すだけでは拾えない論点を次の対話に渡せる。

## 利用シーン

- 初回ヒアリング前に何を聞くか整理したいとき
- 会議中に使う進行カードがほしいとき
- 会議後にボトルネック仮説と次回の確認事項を残したいとき

依頼の例: 「来週の初回ヒアリング準備をしたい」「ヒアリング結果を整理して、次回の擦り合わせ質問もほしい」

## 使い方

**いつ使うか:** 会議前に `mode:prep` を、会議後に `mode:analysis` を使う。指定がなければ会議前の準備から始まる。

**会議前（prep）**

1. ユーザーが営業メモや既知情報を渡し、この会議で得たいことを 1 つに絞る。
2. スキルが分かっていることとまだ聞いていないことを並べ、進行カード、今日聞く質問、カテゴリ別の予備質問を出す。

**会議後（analysis）**

1. ユーザーが会議メモや文字起こしを渡す。
2. スキルが発言と観察から現状を整理し、ボトルネック仮説、解決の方向、次回の擦り合わせ質問を残す。

## 具体例

依頼: 「来週の初回ヒアリング準備をしたい。社内公募アプリを検討していて、部署を越えた応募がほとんど起きていない。」

::: info 出力される進行カードの抜粋:

**1. 今日の会議目的**

社内公募の現状フローと、応募直前で止まる理由を整理し、次回以降に深掘りすべき論点を明確にする。今回の会議では解決策は決めない。

**6. 今日聞く質問**

1. 今は社内公募を、どの経路で知りますか？
   - カテゴリ: Situation
   - 何を確認するためか: 認知から応募までの現状フローを把握するため
2. 募集を見ても応募しないとき、何が止まっていますか？
   - カテゴリ: Problem
   - 何を確認するためか: 応募直前の詰まりを具体化するため

:::

## 前提条件

- 会議前に使うときは、営業メモ、顧客発言、議事録、社内仮説などの断片情報。
- 会議後に使うときは、会議メモ、文字起こし、または会議前に出した進行カードのいずれか。

## 注意事項

- 自動化ありきで結論を先に置かない。発言から現状を拾ってから仮説を書く。
- `questions.md` の全質問をそのまま出さず、この会議の目的に合わせて選ぶ。
