# prhythm-docs

## 概要

調査・分析スキルのチャット結果、または同等のメモや既存 `docs/` 成果物を渡すと、そのスキルの文書テンプレに流し込み、`docs/prhythm/{skill}/` にマークダウン文書とスライド形式の HTML を作成して情報をまとめる。

## 利用メリット

- 提案リードの「で、何？」に答えるための情報がまとまる
- Markdown とスライドが揃うので、非同期共有と同期ミーティングの両方に使える。
- 提案スライドに盛り込む際のたたき台を得られる

## 利用シーン

- 調査スキルを走らせた直後、チャットが流れる前に共有物が欲しいとき
- コンサルや意思決定者への提案で、結論と「決めてほしいこと」を残したいとき
- スライドのビジュアルで情報を考えたいとき

依頼の例: 「ヒアリング結果をまとめて。明日の打ち合わせに持っていきたい。」

## 使い方

**いつ使うか:** 調査・分析スキルを走らせた直後、チャットが流れる前に共有物が欲しいときに入る。対象スキルのあとにだけ使う。複数スキルの結果をまとめて発表用 HTML デッキをつくるときは `create-html-deck`。

1. ユーザーがどのスキル（とモード）の出力をまとめるか指定する。
2. スキルがそのスキルの `templates/docs/` に事実だけを流し込む。無いものは書かない。マークダウンは結論・観測条件・そのスキル固有の表や図 1 つ・決めてほしいこと・次の行為に限る。
3. スキルが `docs/prhythm/{skill}/index.md` と `index.html` を組む。ユーザーが文字数・件数・レイアウトの検査結果を見て、詰め込みを止める。配布用 PDF が要るときはブラウザで開いて Print から Save as PDF する。

## 具体例

依頼: 「社内公募アプリのヒアリング結果をまとめて。明日の打ち合わせに持っていきたい。」

::: info 出力される `docs/prhythm/hearing/index.md` の抜粋:

**Answer**

> **ボトルネックは募集の認知ではなく、手を挙げる瞬間に名前が出ることだ。**

- イントラの募集一覧は見ている
- 応募率が 1.2% なのは、発見不足というより評価を気にして止まるから

:::

## 構成

```text
prhythm-docs/
├── README.md
├── SKILL.md
├── assets/
│   ├── deck.css
│   ├── deck-stage.js
│   └── shell.html
├── scripts/
│   ├── build-deck.mjs
│   └── lint-deck.mjs
├── templates/
│   └── docs/
│       └── index.md          # 新スキル用の共通骨格。出力には使わない
├── examples/
│   └── slot-northline/       # 架空提案の埋済サンプル（10 スキル分）
└── references/
    ├── shared-rules.md
    ├── md-grammar.md         # マークダウンのブロックと情報量
    ├── slide-grammar.md
    └── deck-shell.md
```

新しいスキルを足すときは `templates/docs/index.md` をコピーし、Frame の列と Evidence の表や図だけを差し替える。

## 前提条件

- 整形対象のスキル出力が会話上、または既存ファイルにあること。
- 対象スキルに `templates/docs/index.md` があること。スライドも出すなら `sections.html` も。
- Node.js（ビルドと lint）。`--visual` は `playwright-chromium` を使う。

## 注意事項

- カタログ全量を転記せず、テンプレに載る事実だけを書く。
- HTML シェルは手書きせず、必ず `build-deck.mjs` で組む。
- スライド CSS に `clamp()` や `vw` を持ち込まない。固定キャンバスの前提と lint が壊れる。

## 関連スキル

コアスキル全般が対象。走らせたスキルの出力を打ち合わせ資料にする。複数スキルの結果を発表用 HTML デッキにまとめるときは [create-html-deck](../create-html-deck/README.md)。
