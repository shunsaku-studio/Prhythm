# Phase 2 — Axis Extraction

4 象限の **X / Y 軸** を決める。ここがスキルの分かれ目。確定前に Phase 3 へ進まない。

## Goal

- 自プロダクトにとって **右＝望ましい / 上＝望ましい** になる 2 軸
- 候補を複数出し、ユーザーに選ばせる（または修正させる）
- 「空白の右上」が議論できる軸であること

## How to derive axes

1. Phase 1 の Cluster notes から対立を拾う
2. Desired direction（Phase 0）に照らして、望ましい極を右・上に置く
3. 各軸を **連続したトレードオフ** にする（カテゴリラベルの羅列ではない）
4. サービスが実際にバラける軸にする（全員が同じ象限に落ちる軸は不合格）

## Axis quality bar

良い軸:
- 顧客・提案相手が「どっち向きが嬉しいか」を議論できる
- 既存サービスが最低 3 象限に散る見込みがある
- 右上に「まだ誰も取っていないが取りたい」置き場が想像できる

悪い軸（禁止に近い）:
- `Simple ↔ Feature-rich`
- `Cheap ↔ Expensive` だけ
- `B2B ↔ B2C` だけ
- 自社の機能一覧を軸名にしたもの

### Candidate set B（代替）

| 軸 | 左 / 下 | 右 / 上 | 見えること |
|----|---------|---------|-----------|
| **X** | | | |
| **Y** | | | |

**ここで停止する。** ユーザーに A / B / 修正版のどれでマップするか確認する。

## After user confirms

確定軸を 1 表に固定してから Phase 3 へ。

```markdown
## Confirmed Axes

| 軸 | 低（左/下） | 高（右/上） |
|----|------------|------------|
| **X** | | |
| **Y** | | |

Orientation: 右上 = 自プロダクトが取りにいきたい方向
```
