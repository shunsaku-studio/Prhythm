# market-landscape

## 概要

解きたい課題（またはカテゴリ名）、対象ユーザー、望ましさの仮説を渡すと、参考サービスを集め、軸を決めたうえで 4 象限の地図に並べる。軸の右と上を望ましい方向に取ったとき、まだどのサービスも立っていない領域を、本 README では「空白の右上」と呼ぶ。成果物はその地図と、その領域を一文にしたもの。

## 利用メリット

- 参考サービスを地図上に並べるので、競合がひしめく領域とまだ誰もいない領域をチームで議論できる。
- 汎用の「シンプル対高機能」で終わらせず、このプロダクト固有の軸で差別化の置き場を決められる。
- ヒアリング前に事例調査が共通言語になるので、提案の一手をチームで揃えやすい。

## 利用シーン

- RFP がふわっとしていて、いきなり画面に落とす前に市場の見取り図が欲しいとき
- カテゴリ名しかなく、誰の課題かを揃えてから調査したいとき
- 差別化の置き場が曖昧なとき

依頼の例: 「社内公募まわりの市場地図を作って」「空白の右上を探したい」

## 使い方

**いつ使うか:** 画面やヒアリングの前に、市場の見取り図が欲しいときに入る。地図の仮説を顧客対話で確かめるのは後続の `hearing`、誰向けかを切るのは `defining-personas-and-segments`。

1. ユーザーが解きたい課題、対象ユーザー、望ましさの仮説を渡す。カテゴリ名しかなければ、スキルが 1 問だけ聞く。スキルが Frame（誰のどんな課題か、望む方向）を出してから調べに入る。
2. スキルが参考サービスを調べ、軸の種を出す。
3. スキルが軸の候補を複数提示するので、チームで 1 組選ぶ。軸が決まるまで地図には進まない。
4. スキルが 4 象限にプロットし、まだ誰もいない領域を一文にする。

## 具体例

依頼: 「社内公募まわりの市場地図を作って。現場の声が届きにくい。」

::: info 出力される 4 象限マップの抜粋:

| Service / Cluster | X（現場の声が届く） | Y（部署を越えて手が挙がる） | 根拠 |
|---|---|---|---|
| イントラ掲示板 | 低 | 低 | 掲載は人事起点。応募は上司経由 ※推測 |
| カオナビ / タレントパレット | 中 | 低 | 人材データは溜まるが、手挙げの導線が弱い |
| Slack + スプレッドシート | 高 | 中 | 現場の雑談には乗るが、正式な公募に繋がらない |
| ... | ... | ... | ... |

空白の右上: 現場の声が届いたまま、部署外へ匿名で手が挙がる領域。

:::

## 前提条件

- 解きたい課題、またはカテゴリ名。
- 日英での Web 検索が実行できる環境が必要。

## 注意事項

- 軸の右と上は望ましい方向に取る。向きが逆だと、空いている領域の読み方が壊れる。
- Slack ボットのような非公式チャネルで提供されるサービスは Web 検索から漏れやすい。調査に含め忘れると、実際には競合がいる領域が空白に見えてしまう。
