# create-journey-map

## 概要

ペルソナのヒアリングメモやインタビュー記録を渡すと、ユーザー体験を時系列の台本として描くジャーニーマップ（JM）を返す。現状（As-Is）では課題からインサイトと HMW（How Might We。構造的な問い）まで出し、チームが優先度を決めたあと理想（To-Be）では対比サマリーとプロトタイプ検証用のコアシーン候補まで導く。感情は数値ではなく言葉で描く。

## 利用メリット

- 場所・発話・感情まで描かれるので、チームが同じシーンを思い浮かべられる。
- 表面的な不満の列挙で終わらず、次の打ち手の起点になるインサイトと HMW が揃う。
- チームが合意した HMW をもとに理想体験を描くので、ウィッシュリストになりにくい。
- To-Be から検証すべきコアシーン候補が出るので、プロトタイプで触る場面が見える。

## 利用シーン

- ヒアリングは終えたが、体験全体を捉えきれていないとき
- 課題は感じているが、何に取り組むべきか曖昧なとき
- チームで HMW の優先度を決めたあと、理想の体験を描きたいとき
- プロトタイプで何を検証するか迷っているとき

依頼の例: 「このヒアリングメモから As-Is JM を作って」「合意した HMW をもとに To-Be JM を作って」

## 使い方

**いつ使うか:** ヒアリング断片を時系列の体験にしたいとき、またはチームが HMW の優先度を決めたあとに理想体験を描きたいときに入る。`hearing` と `defining-personas-and-segments` のあとが多い。コアシーンを選んだら `proto-storyboard`、インサイトを一文にするなら `product-vision-and-concept`。指定がなければ現状（As-Is）から始まる。

**現状（As-Is）**

1. ユーザーがペルソナと現状体験の概要を渡す。足りなければスキルが質問する。
2. スキルが場所・発話・行動・感情を時系列の物語にし、インサイトと HMW まで出す。ここで一度止まり、チームが優先度を決める。

**理想（To-Be）**

1. ユーザーが As-Is JM の全文（インサイトと HMW を含む）と、チームが合意した最優先 HMW を渡す。
2. スキルが理想 JM、対比サマリー、検証用のコアシーン候補 2〜4 を出す。どのシーンを試すかは人間が選ぶ。

## 具体例

依頼: 「このヒアリングメモから As-Is JM を作って。営業企画の佐藤さんが社内公募を見て、応募の直前で止まっている。」

::: info 出力される台本の抜粋:

【応募の直前】

状況：
  金曜 18 時、営業企画のデスク。イントラの募集一覧に「販促データの可視化を手伝ってほしい」と出ている。

発話 / 内心の声：
  「面白そう。でも手を挙げたら、今の部署にどう思われるだろう。」

行動：
  募集タイトルを開いて閉じる。応募ボタンまでは行かない。

感情：
  興味はあるが、評価を気にして指が止まる。

タッチポイント：
  イントラの募集一覧

課題：
  手を挙げる瞬間に名前が出るのが怖い。

:::

## 前提条件

- ペルソナの基本属性と、現状の体験の概要（ヒアリングメモ、議事録など）。
- To-Be を描くときは、As-Is JM の全文と、チームが合意した最優先 HMW。

## 注意事項

- ヒアリング情報が不足する箇所は推測で補い、`※推測` と明示する。必須情報が欠けている場合は生成せず質問する。
- 感情は 1〜5 のような数値スコアでは表現せず、言葉で描く。
