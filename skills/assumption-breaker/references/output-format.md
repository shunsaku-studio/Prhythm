# Output Format — Phase 3 統合出力

## 最終出力の構造

```markdown
# Assumption Breaker: [入力ドキュメント名 or トピック]

## 元の提案サマリ
**課題:** ...
**求められている解:** ...
**明示制約:** ...

## 暗黙の前提（N個）

| # | 前提 | レンズ |
|---|------|--------|
| 1 | ... | ... |

---

## 代替解マップ

| # | 代替解 | 崩した前提 | 使ったムーブ | インパクト | 実現難易度 | 距離 |
|---|--------|-----------|-------------|-----------|-----------|------|
| A | ... | #1 | 手段と目的の分離 | 高 | 中 | 中 |
| B | ... | #1 | 異業種アナロジー | 中 | 低 | 遠 |
| C | ... | #2 | 削除ムーブ | 高 | 高 | 遠 |
| ... |

### 組み合わせ解

| # | 組み合わせ | 含む代替解 | 何が変わるか |
|---|-----------|-----------|-------------|
| X | ... | A + C | ... |
| Y | ... | B + D | ... |

---

## 推奨 3 picks

### 🎯 最もインパクトが大きい: [解の名前]
[1–2文の要約。なぜインパクトが大きいか]

### 🚀 最もラディカル: [組み合わせ解の名前]
[1–2文の要約。何がラディカルか]

### 🔧 最も穏当（前提を1つだけ外す）: [解の名前]
[1–2文の要約。元RFCからの変更が最小限であること]

---

## 元RFCへの問い返し（推奨）

[ここに、RFCの著者に投げかけるとよい問いを2–3個書く。
代替解そのものではなく、著者が自分で前提を再考するきっかけになる問い。]
```

## 注意事項

- **インパクト/難易度/距離** は 高/中/低 の3段階。細かいスコアリングは不要
- **組み合わせ解** は必ず1つ以上出す。単体解の列挙だけで終わらない
- **推奨 3 picks** は必ず3つ。「元RFCのままが最善」の場合は🔧で「元RFC + 小改善」を推す
- **問い返し** は代替解の押し売りではなく、対話のきっかけ。疑問形で書く
