Skills

Prhythm詳細

プロダクトマネジメントの各観点（ビジネス・UX・開発）+デリバリーの実行計画で考えるべきことを、代表的なスキルとして型で提供。ただつくるだけでなく、プロダクトの解像度を多面的に上げ、提案品質を底上げする。

観点 代表的なスキル（成果物） 考えられること
ビジネス ビジネスモデル／放置コスト試算／成功指標 このプロダクトは何で成立するか。やらない場合のコストは何か。何をもって成功とするか
UX ペルソナ／ジャーニーマップ／ユースケース 誰が、どんな流れで、何のために使うのか
開発 モデリング・スキーマ／外部依存・非機能の整理 データ構造はどうなるか。外部依存・非機能の制約はどこにあるか
実行計画 フェーズ・スコープ設計／Go/No-Go基準／体制プラン どこから作り、何で判断し、どんな体制で進めるか

ただプロトをつくるだけでなく、プロダクトの解像度を多面的に上げ、提案品質を底上げする

瞬作スタジオ / Prhythm PM紹介06-1
Demo Skill 02 / 08

ヒアリング

協働：PM × ビジネス skill: hearing-digest

市場の地図を踏まえ、顧客の言葉で事実と仮説を切り分ける。

QUESTIONS

スキルが生成する質問リスト（例）

Q1現行の社内公募は年何回・どんなフローで回していますか？

Q2応募率1.2%はどう計測していますか？部署外応募の内訳は？

Q3応募に上司の承認は必要ですか？いつ・誰に知られますか？

Q4不採用時、結果は誰にどう伝わりますか？

Q5Slack #異動相談は公募とどう関係していますか？

OUTPUT

ヒアリング結果を事実と仮説に分離

FACTS（事実）
  • 公募は年2回・書類選考制。応募率は全社員の1.2%
  • 応募には現上司の承認欄がある（気まずさの元凶）
  • 不採用時、結果が本人と上司の両方に通知される
  • Slack #異動相談 には月40件の書き込みがある
HYPOTHESES（未検証仮説）
  • core 上司に知られずに探索できれば、潜在応募者は動く
  • core 「異動」より「週1日の兼務」なら心理障壁が1/10になる
  • 受け入れ側の部署は、正式求人より「手伝ってほしい仕事」を多く持つ
WHY THIS SKILL

参考調査で見つけた空白地帯を、顧客の実態で検証する。FACTS と HYPOTHESES を分けることで、提案が「思いつき」ではなく「検証可能なストーリー」になる。

PMの判断：何を事実とし、どの仮説を次工程で検証するか。
クリエイターの視点：顧客の声を FACTS / HYPOTHESES に分け、思いつきを検証可能なストーリーに変える。

瞬作スタジオ / Prhythm PM紹介06-3
Demo Skill 04 / 08

ビジョン・コンセプト

協働：PM × ビジネス skill: product-vision

ジャーニーの To-Be を、提案の核となるビジョンとコンセプトに言語化する。

VISION

キャリアの選択肢が、社内にあることが当たり前になる。

CONCEPT

「異動じゃなく、まず越境から」

ウチナカ公募は求人サイトではなく、週1日・3ヶ月から試せる「越境ミッション」のマーケットプレイス。転職級の決断を求めず、小さな越境の成功体験を積み上げる。

REJECTED（棄却案）
  • 「社内転職サイト」 — 心理障壁が As-Is と同じ。復活条件：越境経由の異動が文化として定着した後
  • 「上司推薦型マッチング」 — core仮説①（秘匿性）と正面衝突するため棄却
WHY THIS SKILL

きれいな言葉を作るのが目的ではない。ビジョンと棄却案を並べ、追加要望を採用するか見送るかの判断基準をチームで持つ。

PMの判断：顧客・予算・制約に照らし、提案の核と作らないものを決める。
クリエイターの視点：UXと技術の観点から案を出し、判断基準として使える言葉へ磨く。
